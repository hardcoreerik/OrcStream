# P1 host validation — 2026-11-10

**Scope:** deterministic offline host tests only; no SDR device, USB, Ethernet, Wi-Fi or embedded hardware. Local sandbox Linux x86-64; GCC 14.2.0, Clang 17.0.0, CMake 3.31.6. Host CPU is not a named calibrated benchmark machine; results are provisional.

## Baseline and outcomes

- Reviewed experimental original `tests/test_orcstream.c` and retained the original codec logic. Locally reconstructed the original C99 codec and unit test; baseline Debug build: **1/1 CTest passed**. The experimental file/UDP demos were reviewed, but not independently rerun as the local baseline; the prior 3/3 figure in experimental HANDOFF remains only its historical reported evidence.
- P1: GCC/Clang × Debug/Release, `-Werror`: **2/2 CTest tests passed in each of four configurations**.
- P1: Clang Debug with AddressSanitizer + UndefinedBehaviorSanitizer, `-Werror`: **2/2 tests passed**.
- `independent_iq_roundtrip.py`: **24 raw producer/consumer roundtrips**, 6 formats × 4 packet sizes, 20,017 complex samples per case; per-format source/reconstructed SHA-256 matches; **16 negative streams rejected**.
- Clang libFuzzer+ASan+UBSan: 10,000 empty-corpus randomized runs and 20,000 seeded mutation runs, no reported crash. This is a bounded fuzz smoke check, not a security audit or exhaustive parser verification.
- Windows and macOS are **CI-configured, not observed as passed**; ESP-IDF/esp32p4 compiler not present, so no embedded build compatibility result. No real hardware or client interoperability tests.

## Host microbenchmark (not a network test)

`orcstream_bench` uses C99 `clock()` process CPU time, 64–65,536-byte payloads and a standalone copy of the same bitwise IEEE CRC32 loop. The last local run at **CS16 LE, 2.4 MS/s** reported:

| Payload bytes | Encode payload MB/s | Decode payload MB/s | CRC-only MB/s | Header overhead | Required ideal frame MB/s |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 1,152 | 101.81 | 99.87 | 98.01 | 5.263% | 10.133 |
| 32,768 | 106.69 | 60.48 | 96.11 | 0.195% | 9.619 |
| 65,536 | 107.05 | 106.62 | 102.71 | 0.098% | 9.609 |

At CS16 960 kS/s the raw payload requirement is 3.84 MB/s; at 2.4 MS/s it is 9.6 MB/s. For CF32 at 2.4 MS/s it is 19.2 MB/s, before headers/network. These are calculations, not link throughput. No calibrated CPU utilization or per-core power measurement; timings are noisy single-host figures (including one anomalously slow 32,768-byte decode run), not superiority claims.

**Memory:** stateless core encode/decode uses no heap; `orcstream_reader` needs 64–65,600 bytes of caller-provided storage depending on accepted maximum frame. Demo producer reserves 32,768-byte payload plus 32,832-byte output buffers; consumer reserves 65,600-byte reader plus 113-byte input chunk, plus standard I/O runtime state. `orcstream_bench` uses `malloc` only in the standalone benchmark. No buffer grows with packets processed. Separate malloc/free checks and embedded stack sizing are outstanding.

## Reproduce with log

Run from repo root. The full log is written to `./orcstream-p1-test.log` (same directory as the test commands). Do not redirect logs to a build subfolder. Run `bash ./tests/run-p1.sh`; it prints compiler versions, command lines, test outcomes, fuzz evidence when Clang supports libFuzzer and benchmark results.
